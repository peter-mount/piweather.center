\subsectionpaged{Calculate}
\label{config:calculate}
\index{calculate}
\index{Config!calculate}

\begin{lstlisting}[language=Go,style=kaolstplain]
calculate( "target.metric.name"
    [every "crontab"]
    [reset every "crontab"]
    [load "when" with "expression"]
    [usefirst "metric"]
    as (*\textit{expression}\dots*)
)
\end{lstlisting}

\Statement{calculate} defines a calculation to be performed at either regular intervals or whenever one or more
metrics change value.

\ParameterDescription{
\item[every]defines when the calculation should be performed over time.
This is usually used for periodic calculations that do not depend on metrics.
For example calculating the Sun's altitude at the weather station.

\item[reset every]defines when the metric being calculated should be reset to some default value by using
the \textbf{load} option.

\item[load]defines a database expression to perform and the range of time to retrive it, to get the metric's initial value.
This is usually performed when the \ServiceName{calculator} starts, however it can also be called periodically with
the \textbf{reset every} option.
\item[usefirst]defines a metric to use as the initial value if a metric has no value or is being reset by
\textbf{reset every} and \textbf{load} has not returned any value.

\item[as]is the expression to perform whenever the calculation is performed.
If the expression references any metrics then they become triggers so that, whenever they are updated then this
calculation is performed.
}

\subsubsection{Example calculation}
\label{subsec:config:calculate:simple}
This example shows how a calculation can be performed whenever one or more metric's are updated.
Here we will calculate the \vrefMargin{Heat Index}{sec:HeatIndex} using metrics for temperature and humidity.
The following calculation will calculate the \GoFuncRef{HeatIndex} using \Metric{ecowitt.temp} and
\Metric{ecowitt.humidity} as the function's parameters.
The result will be converted into Celsius and stored into the metric \Metric{ecowitt.heatIndex}.

\begin{lstlisting}[language=Go,caption={Example calculation},escapechar=|]
calculate( "ecowitt.heatIndex" |\label{line:calculate:simple:target}|
    as heatIndex( "ecowitt.temp", "ecowitt.humidity" ) |\label{line:calculate:simple:as}|
)
\end{lstlisting}

Line \ref{line:calculate:simple:target} declares we are calculating the metric \Metric{ecowitt.heatIndex.max}.

Line \ref{line:calculate:simple:as} is the expression where we use the heatIndex function,
passing the metrics \Metric{ecowitt.temp} and \Metric{ecowitt.humidity}.

\subsubsectionfit{Example calculation with no metrics}
\label{subsec:config:calculate:nometric}
Calculations don't always require a source metric.
Some are based on the stations location and/or the time of day for their results.
In this example we calculate the Sun's altitude at the weather station for the time of day:

\begin{lstlisting}[language=Go,caption={Example calculation with no metrics},escapechar=|]
calculate( "local.solarAltitude"     |\label{line:calculate:nometric:target}|
    every "minute"                   |\label{line:calculate:nometric:every}|
    as solarAltitude() unit "degree" |\label{line:calculate:nometric:as}|
)
\end{lstlisting}

As before, line \ref{line:calculate:nometric:target} declares we are calculating the metric \Metric{local.solarAltitude}.

\marginnote{Calculating the Sun's location is better performed by \Statement{ephemeris} in \vref{config:ephemeris}}
Line \ref{line:calculate:nometric:every} causes the calculation to be performed once every minute,
whilst line \ref{line:calculate:nometric:as} uses the \GoFunction{solarAltitude} function for the calculation.
This function uses no metrics but does use the stations location and the current time.

\subsubsectionfit{Example aggregation}
Aggregations like min, max \etc can be used as a function just like in \vref{subsec:config:calculate:simple}.

\marginnote{This example can be simplified with \Statement{calculate from} in \vref{config:calculateFrom}}
The following calculation will automatically record the maximum value of a metric for the current day:

\begin{lstlisting}[language=Go,caption={Example aggregation calculation},escapechar=|]
calculate( "ecowitt.heatIndex.max" |\label{line:calculate:aggregator:target}|
    reset every "day" |\label{line:calculate:aggregator:reset}|
    load "today" with "max(ecowitt.heatIndex)" |\label{line:calculate:aggregator:load}|
    usefirst "ecowitt.heatIndex" |\label{line:calculate:aggregator:usefirst}|
    as max( current,"ecowitt.heatIndex") |\label{line:calculate:aggregator:as}|
        unit "celsius" |\label{line:calculate:aggregator:unit}|
)
\end{lstlisting}

Line \ref{line:calculate:aggregator:target} declares we are calculating \Metric{ecowitt.heatIndex.max}.

Line \ref{line:calculate:aggregator:reset} indicates the metric will be reset once every day at midnight.

Line \ref{line:calculate:aggregator:load} will, when either the \CalculatorService starts,
or the reset on line \ref{line:calculate:aggregator:reset} triggers, get the initial value from the database as
the maximum value since midnight.

If no value is in memory (either on startup or the database returned no values),
then line \ref{line:calculate:aggregator:usefirst} ensures that we do have a value by using the current value of
\Metric{ecowitt.heatIndex}.

Finally line \ref{line:calculate:aggregator:as} declares the expression to calculate.
In this instance to use the maximum of the current value of \Metric{ecowitt.heatIndex.max} and \Metric{ecowitt.heatIndex}
and storing the result in Celsius.

Because we reference \Metric{ecowitt.heatIndex.max} in the calculation, it becomes a trigger so whenever it is updated
then the calculation is performed.
